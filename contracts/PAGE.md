# Page / Screen contract

Read this when changing the composition, actions or information hierarchy of an ordinary phone/tablet page. It is not required when only changing the internals of a reusable component.

## Start with the task

State the page's primary user task in one sentence and optimise the page for that path. A page is not a catalogue of every operation the underlying data supports.

## Action hierarchy

- Give the primary task an evident primary action.
- Add a visible secondary action only when the current task needs immediate access to it.
- Prefer removing, relocating, consolidating or progressively disclosing nonessential actions rather than adding another button.
- Do not add an overflow menu merely to preserve actions that do not belong on the page.
- Keep equivalent actions in consistent locations across equivalent pages.

The page decides whether an action belongs. The button contract decides how a button renders.

## Information hierarchy

Distinguish identity, primary content, contextual information and secondary metadata. Do not give every fact equal visual weight and do not repeat information unless the repetition helps the task.

## Phone and tablet composition

- Start with a usable single-column phone layout without horizontal scrolling.
- On tablet, use extra space when it strengthens the primary task: scanning, imagery, comparison or direct interaction.
- Do not add panels, columns or controls simply because tablet width is available.
- When space is constrained, secondary metadata and redundant instruction yield before the primary task and its required actions.
- Content determines container size unless a fixed area has a functional reason such as a board, map, canvas or editor.

## Scrolling

The page normally owns its scrolling. Avoid unnecessary nested scroll areas. Scrolling is expected on phones, but it is not a substitute for information hierarchy.

## Lists

For large collections, consider grouping, compact rows, grids, search/filter or progressive disclosure where they genuinely help. Do not simply turn a large dataset into an endlessly long page.
