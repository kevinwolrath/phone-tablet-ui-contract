# Global principles

This is intentionally small. A normal change should not begin by reading a large rule book.

## Primary task first

The main thing the user came to do should be obvious and visually dominant.

## Fewer visible actions

The fact that the software can perform an operation does not mean that operation needs its own control on every screen. Keep secondary operations out of the way of the main task.

## Phone first

Start with touch interaction and phone-sized layouts, then use tablet space where it improves the same task. Do not treat extra width as a reason to add more controls.

## Shared patterns

Prefer existing shared components and interaction patterns. If the same behaviour is being recreated on several screens, move it towards a shared owner.

## Accessible meaning

State and meaning should remain understandable without relying on colour alone.
